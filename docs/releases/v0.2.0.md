# exfetch 0.2.0

A versioned release of the completed local browser-retrieval path and request-policy fixes.

- Standalone `fetch --browser` uses the authenticated running bridge; MCP browser requests use the extension attached to their own process.
- Configured domains, actions and cookie scope are enforced, including redirect and screenshot-target checks. Malformed or unknown configuration fields fail instead of silently resetting policy.
- CSS selection, search output formats and configured defaults work across the documented entry points.
- PDF and transport dependencies include the reviewed security updates.

Archives contain binaries for Linux x86-64 and macOS Intel/Apple Silicon, plus an unpacked Chrome extension source ZIP and SHA256SUMS. The Chrome ZIP is loaded through Developer mode; it is not a Chrome Web Store package. Safari source remains available in the repository and requires Xcode conversion, signing and device validation. No Safari application is included.

Viewport screenshots now request Chrome's required `<all_urls>` host permission; page actions still reject file, data and browser-internal targets. Reloading an existing unpacked extension may require reviewing its site-access permission.

These are local developer tools, with browser access to the session you control. The domain rules are not a browser network firewall or a multi-user isolation boundary. Existing live binaries and client configurations are not automatically changed. See [release validation](../RELEASE_VALIDATION.md) for tested clients and limits.
